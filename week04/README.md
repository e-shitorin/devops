# 4주차 - 자동화와 협업

## 1. 실습 환경

- Ubuntu (WSL)
- Bash
- Git 및 GitHub

## 2. 셸 스크립트 기초

### `check.sh`

입력한 경로가 파일인지 디렉터리인지 확인한다.

- `-z`: 입력값이 비어 있는지 확인
- `-f`: 일반 파일인지 확인
- `-d`: 디렉터리인지 확인
- 잘못된 입력이나 존재하지 않는 경로에 대해 종료 상태 `1`을 반환

### `greet.sh`

명령줄 인자를 받아 사용자에게 인사한다.

- `$1`: 첫 번째 인자
- `$#`: 전달된 인자의 개수
- 인자가 없으면 사용법을 출력하고 종료한다.

### `var.sh`

변수와 명령어 치환을 연습한다.

- 변수 `USERNAME`에 문자열 저장
- `$(date +%Y%m%d)`로 날짜 생성
- 날짜를 파일명 형식에 결합

## 3. 백업 자동화

### `backup.sh`

백업 스크립트는 지정한 디렉터리를 `.tar.gz` 파일로 압축하고 결과를 기록한다.

1. 스크립트 위치로 이동
2. 백업할 디렉터리 확인
3. `backups` 디렉터리 생성
4. 날짜와 프로세스 ID를 이용해 백업 파일명 생성
5. `tar -czf`로 압축
6. 종료 상태를 확인하고 파일 크기 출력
7. 백업 파일 목록과 로그 기록

기본 실행:

```bash
cd week04
bash backup.sh
```

특정 디렉터리 지정:

```bash
bash backup.sh test
```

## 4. GitHub 협업 과정

Week 04 실습 결과는 별도 브랜치에서 작업한 뒤 Pull Request를 생성하여 `main` 브랜치에 병합하였다.

- 변경 사항을 브랜치에서 작업
- 커밋으로 변경 이력 기록
- Pull Request로 변경 사항 제안
- 병합 후 `main`에 결과 반영

관련 Pull Request: [#1 - Add week04 automation practice](https://github.com/e-shitorin/devops/pull/1)

## 5. 학습 정리

- 조건문과 파일 검사

- 변수 및 명령어 치환
- `tar`를 이용한 압축 백업
- 종료 상태 코드와 오류 처리
- 백업 로그 기록
- Git 브랜치와 Pull Request를 통한 변경 이력 관리
